# Coding Agent - 评审回应阶段

## 输入文档

- **TASK_UNIT_{name}_CODE_REVIEW.md**: Code Reviewer 的评审问题
- **修改后的代码文件**: 根据评审要求修改的代码

## 输出文档

- **TASK_UNIT_{name}_CODE_REVIEW_FEEDBACK.md**: 对评审问题的反馈
- **修改后的代码文件**: 根据评审要求修改的代码（如有）

## 工作流程

### Step 1: 阅读评审文档

1. 阅读 TASK_UNIT_{name}_CODE_REVIEW.md
2. 理解每个评审问题

### Step 2: 逐一回应评审问题

对于每个评审问题，判断：

```
1. 接受修改:
   - 按评审要求修改代码
   - 在反馈文档中记录"已修改"
   - 确保修改后测试仍然通过

2. 拒绝修改:
   - 提出拒绝理由
   - 例如: 与 API-SPEC.md 定义冲突、与设计文档冲突等
   - 在反馈文档中记录拒绝理由

3. 需要澄清:
   - 如果评审问题与设计文档有矛盾
   - 输出 DOCUMENT_CONFLICT.md，请求人工介入
```

### Step 3: 修改代码后重新运行测试

如果接受了评审问题并修改了代码：
1. 运行所有测试（前端 + 后端 + 集成）
2. 确保测试仍然通过
3. 确保覆盖率仍然达标

### Step 4: 输出反馈文档

输出 TASK_UNIT_{name}_CODE_REVIEW_FEEDBACK.md。

## 提示词样例

```
你需要阅读当前项目目录下的 TASK_UNIT_{name}_CODE_REVIEW.md 文档，这是 Code Reviewer 对你代码的评审问题。

请逐一审阅每个问题:

1. 如果接受评审问题:
   - 按评审要求修改代码
   - 在反馈文档中记录"已修改"
   - 修改后重新运行所有测试，确保测试通过

2. 如果不接受评审问题:
   - 提出拒绝理由
   - 例如: 与 API-SPEC.md 定义冲突、与 FRONTEND-DESIGN.md 冲突等
   - 在反馈文档中记录拒绝理由

3. 如果评审问题与设计文档有矛盾:
   - 输出 DOCUMENT_CONFLICT.md，请求人工介入

请将反馈输出到 TASK_UNIT_{name}_CODE_REVIEW_FEEDBACK.md 文档。
```
