# Code Reviewer - 反馈处理阶段

## 评审模式判断

| 输入信号 | 评审模式 |
|---------|---------|
| TASK_UNIT_{name}_CODE_REVIEW_FEEDBACK.md | 任务单元评审反馈 |
| BUG-FIX_REVIEW_FEEDBACK.md | 缺陷修复评审反馈 |

## 场景 1: 任务单元评审反馈

### 输入文档

- **TASK_UNIT_{name}_CODE_REVIEW_FEEDBACK.md**: Coding Agent 对评审问题的反馈
- **修改后的代码文件**: 根据评审要求修改的代码（如有）

### 输出文档

- **TASK_UNIT_{name}_CODING_APPROVE.md**: 批准通过文档（全部达成一致时）
- **TASK_UNIT_{name}_CODE_REVIEW_FEEDBACK-{n}.md**: 继续追问文档（仍有问题时）
- **REVIEW_PAUSED.md**: 需人工介入时输出
- **PROJECT-STATUS-CR.md**: CR 评审度量数据（评审通过时追加）

### 工作流程

1. 阅读 TASK_UNIT_{name}_CODE_REVIEW_FEEDBACK.md
2. 逐一审阅每个问题的反馈
3. 判断:
   - **接受修改**: 验证代码已修改，记录确认
   - **接受拒绝**: 拒绝原因合理，撤回该问题
   - **继续追问**: 不接受拒绝原因，继续提出理由
   - **需要人工介入**: Coding Agent 指出设计文档矛盾，暂停评审，请求人工介入
4. 处理结果:
   - 全部达成一致 → 生成 TASK_UNIT_{name}_CODING_APPROVE.md
   - 仍有问题 → 生成 TASK_UNIT_{name}_CODE_REVIEW_FEEDBACK-1.md（编号递增）
   - 需人工介入 → 输出 REVIEW_PAUSED.md，等待人工介入

## 提示词样例

```
你需要阅读当前项目目录下的 TASK_UNIT_{name}_CODE_REVIEW_FEEDBACK.md 文档，这是 Coding Agent 对你评审问题的回复。

请逐一审阅每个问题的反馈:

1. 如果 Coding Agent 已接受问题:
   - 确认是否已修改对应代码
   - 验证修改是否符合评审要求
   - 确认修改后测试仍然通过

2. 如果 Coding Agent 不接受问题:
   - 审阅其拒绝理由
   - 如果拒绝理由合理，撤回该问题
   - 如果不接受其拒绝理由，继续提出你的理由

3. 如果 Coding Agent 指出设计文档矛盾:
   - 输出 REVIEW_PAUSED.md，暂停评审
   - 请求人工介入

处理结果:
- 如果所有问题已达成一致，且代码已按要求修改，生成 TASK_UNIT_{name}_CODING_APPROVE.md 文档
- 如果仍有未解决问题，生成 TASK_UNIT_{name}_CODE_REVIEW_FEEDBACK-1.md 文档，继续追问
- 如果需人工介入，输出 REVIEW_PAUSED.md

只有当所有问题你和 Coding Agent 都达成一致，并确认代码已按要求修改时，才生成批准文档。

通过后，请更新 PROJECT-STATUS-CR.md，追加该任务单元的评审度量数据。
```
