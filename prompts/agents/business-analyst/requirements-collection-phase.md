# Business Analyst - 需求收集阶段

## 输入文档

- 用户想法/口头需求: 用户通过对话表达的模糊想法

## 输出文档

- **BRD.md**: 业务需求文档
  - 项目背景与目标
  - 目标用户群体
  - 核心功能需求
  - 功能优先级排序 (P0/P1/P2)
  - 业务边界与约束
  - 验收标准

## 工作流程

1. 启动 `/office-hours` 或 `/brainstorming` skill，进入开放式需求收集模式
2. 通过对话帮助用户:
   - 明确项目背景和目标
   - 识别目标用户群体
   - 梳理核心功能需求
   - 定义功能优先级
   - 确定业务边界和约束
3. 对话结束后，将收集的需求结构化输出到 BRD.md

## 提示词样例

```
/office-hours 我想做一款学习键盘打字软件，从最简单的单个字母输入开始练习，到大段文章，简单的字母可以根据每只手指负责的键盘位置来进展练习，然后不断进阶，最后综合双手输入。
```

## BRD.md 文档结构规范

```markdown
# 业务需求文档 (BRD)

## 1. 项目背景
- 项目名称
- 项目背景描述
- 项目目标

## 2. 目标用户
- 用户群体描述
- 用户痛点分析
- 用户价值主张

## 3. 功能需求

### 3.1 核心功能 (P0)
- 功能1: [描述]
- 功能2: [描述]

### 3.2 重要功能 (P1)
- 功能1: [描述]

### 3.3 可选功能 (P2)
- 功能1: [描述]

## 4. 业务边界
- 包含范围
- 不包含范围
- 约束条件

## 5. 验收标准
- [验收条件1]
- [验收条件2]
```
