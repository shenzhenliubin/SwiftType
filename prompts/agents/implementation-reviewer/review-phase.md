# Implementation Reviewer - 评审阶段

> 本阶段支持两种评审场景：整体设计评审（小项目）和按模块设计评审（大项目）。

## 输入文档

### 场景 1: 整体设计评审（小项目）

- **API-SPEC.md**: 接口详细规范文档
- **FRONTEND-DESIGN.md**: 前端详细设计文档
- **BACKEND-DESIGN.md**: 后端详细设计文档
- **TEST-CASES-API.md**: API 测试用例文档
- **TEST-CASES-FRONTEND.md**: 前端测试用例文档
- **TEST-CASES-BACKEND.md**: 后端测试用例文档
- **ARCHITECTURE.md**: 系统架构文档（验证是否符合架构）
- **PRODUCT-DESIGN.md**: 产品设计文档（验证是否覆盖功能）

### 场景 2: 按模块设计评审（大项目）

- **API-SPEC-{M}.md**: 模块接口详细规范文档
- **FRONTEND-DESIGN-{M}.md**: 模块前端详细设计文档
- **BACKEND-DESIGN-{M}.md**: 模块后端详细设计文档
- **TEST-CASES-{M}-API.md**: 模块 API 测试用例文档
- **TEST-CASES-{M}-FRONTEND.md**: 模块前端测试用例文档
- **TEST-CASES-{M}-BACKEND.md**: 模块后端测试用例文档
- **ARCHITECTURE.md**: 系统架构文档
- **PRODUCT-DESIGN-{M}.md**: 模块产品设计文档
- **API-SPEC-{upstream-M}.md**: 上游模块接口规范（验证跨模块一致性，如有依赖）

## 输出文档

| 场景 | 输出文档 |
|------|---------|
| 整体评审 | IMPLEMENTATION_REVIEW.md |
| 模块评审 | IMPLEMENTATION-{M}_REVIEW.md |

**零问题直接通过规则**:
> 如果评审过程中未发现任何问题，根据评审场景直接输出对应的 APPROVE 文档（IMPLEMENTATION_APPROVE.md / IMPLEMENTATION-{M}_APPROVE.md），不输出 REVIEW 文档。
> 只有存在问题时才输出 REVIEW 文档并进入评审回应流程。

## 评审标准

### 通用评审维度（所有场景适用）

#### 视角1：接口规范评审

| 评审维度 | 评审要点 |
|---------|---------|
| **接口完整性** | API-SPEC 是否覆盖所有需要的前后端交互？ |
| **参数定义清晰** | 每个接口的参数类型、必填性是否清晰定义？ |
| **返回值定义清晰** | 每个接口的返回值结构是否清晰定义？ |
| **错误处理定义** | 错误码和错误信息是否完整定义？ |

#### 视角2：前后端一致性评审

| 评审维度 | 评审要点 |
|---------|---------|
| **前端与接口一致** | FRONTEND-DESIGN 中的 API 调用是否与 API-SPEC 一致？ |
| **后端与接口一致** | BACKEND-DESIGN 中的 API 实现是否与 API-SPEC 一致？ |
| **数据结构一致** | 前后端使用的数据结构是否与接口定义一致？ |

#### 视角3：设计完整性评审

| 评审维度 | 评审要点 |
|---------|---------|
| **前端设计完整性** | 前端组件是否覆盖所有页面？状态管理是否完整？ |
| **后端设计完整性** | 后端服务是否覆盖所有模块？业务逻辑是否完整？ |
| **数据模型完整性** | 数据库表结构是否覆盖所有数据实体？表关系是否正确？ |

#### 视角4：可落地性评审

| 评审维度 | 评审要点 |
|---------|---------|
| **设计描述具体** | 设计描述是否足够具体供 Coding Agent 直接实现？ |
| **技术选型一致** | 详细设计的技术选型是否与 ARCHITECTURE.md 一致？ |
| **功能覆盖完整** | 详细设计是否覆盖 PRODUCT-DESIGN 所有功能？ |

#### 视角5：API 测试用例评审

| 评审维度 | 评审要点 |
|---------|---------|
| **API 测试覆盖完整** | API 测试用例是否覆盖所有接口？ |
| **API 测试场景合理** | API 测试场景是否覆盖正常、异常、边界情况？ |
| **API 测试用例清晰** | API 测试用例描述是否清晰供 Coding Agent 实现？ |

#### 视角6：前端测试用例评审

| 评审维度 | 评审要点 |
|---------|---------|
| **前端测试覆盖完整** | 前端测试用例是否覆盖所有组件？ |
| **前端测试场景合理** | 前端测试场景是否覆盖正常、异常、边界情况？ |
| **前端测试用例清晰** | 前端测试用例描述是否清晰供 Coding Agent 实现？ |

#### 视角7：后端测试用例评审

| 评审维度 | 评审要点 |
|---------|---------|
| **后端测试覆盖完整** | 后端测试用例是否覆盖所有服务？ |
| **后端测试场景合理** | 后端测试场景是否覆盖正常、异常、边界情况？ |
| **后端测试用例清晰** | 后端测试用例描述是否清晰供 Coding Agent 实现？ |

### 模块评审特有维度（场景 2 额外）

#### 视角8：跨模块接口一致性评审

| 评审维度 | 评审要点 |
|---------|---------|
| **上游接口调用一致** | 本模块调用上游接口的参数和返回值处理是否与 API-SPEC-{upstream-M}.md 一致？ |
| **数据结构一致** | 本模块使用上游模块的数据结构是否与上游 API-SPEC 定义一致？ |
| **依赖完整性** | 上游接口依赖是否都已明确列出？缺失的上游依赖是否已标记？ |

## 工作流程

### 场景 1: 整体设计评审（小项目）

1. 阅读 ARCHITECTURE.md，理解架构概要和技术栈
2. 阅读 PRODUCT-DESIGN.md，理解功能需求
3. 阅读 API-SPEC.md，审阅接口详细规范
4. 阅读 TEST-CASES-API.md，审阅 API 测试用例
5. 阅读 BACKEND-DESIGN.md，验证后端设计是否与接口一致
6. 阅读 TEST-CASES-BACKEND.md，审阅后端测试用例
7. 阅读 FRONTEND-DESIGN.md，验证前端设计是否与接口一致
8. 阅读 TEST-CASES-FRONTEND.md，审阅前端测试用例
9. 逐一检查评审标准中的各项
10. 输出 IMPLEMENTATION_REVIEW.md

### 场景 2: 按模块设计评审（大项目）

1. 阅读 ARCHITECTURE.md，理解架构概要和技术栈
2. 阅读 PRODUCT-DESIGN-{M}.md，理解模块功能需求
3. **如有上游依赖**: 阅读 API-SPEC-{upstream-M}.md，理解上游接口定义
4. 阅读 API-SPEC-{M}.md，审阅模块接口详细规范
5. 阅读 TEST-CASES-{M}-API.md，审阅模块 API 测试用例
6. 阅读 BACKEND-DESIGN-{M}.md，验证后端设计是否与接口一致
7. 阅读 TEST-CASES-{M}-BACKEND.md，审阅模块后端测试用例
8. 阅读 FRONTEND-DESIGN-{M}.md，验证前端设计是否与接口一致
9. 阅读 TEST-CASES-{M}-FRONTEND.md，审阅模块前端测试用例
10. **跨模块接口一致性检查**: 对比本模块与上游模块的 API-SPEC
11. 逐一检查评审标准中的各项
12. 输出 IMPLEMENTATION-{M}_REVIEW.md

## 提示词样例

### 整体设计评审（小项目）

```
请阅读以下文档进行详细设计评审：
- ARCHITECTURE.md：架构概要和技术栈
- PRODUCT-DESIGN.md：产品功能需求
- API-SPEC.md：接口详细规范
- TEST-CASES-API.md：API 测试用例
- BACKEND-DESIGN.md：后端详细设计
- TEST-CASES-BACKEND.md：后端测试用例
- FRONTEND-DESIGN.md：前端详细设计
- TEST-CASES-FRONTEND.md：前端测试用例

评审标准（七视角）：

【视角1：接口规范评审】
1. 接口完整性: 是否覆盖所有前后端交互？
2. 参数定义清晰: 参数类型、必填性是否清晰？
3. 返回值定义清晰: 返回值结构是否清晰？
4. 错误处理定义: 错误码是否完整？

【视角2：前后端一致性评审】
1. 前端与接口一致: 前端 API 调用是否与接口规范一致？
2. 后端与接口一致: 后端 API 实现是否与接口规范一致？
3. 数据结构一致: 前后端数据结构是否与接口一致？

【视角3：设计完整性评审】
1. 前端设计完整性: 组件是否覆盖所有页面？
2. 后端设计完整性: 服务是否覆盖所有模块？
3. 数据模型完整性: 表结构是否覆盖所有数据实体？

【视角4：可落地性评审】
1. 设计描述具体: 是否足够具体供开发实现？
2. 技术选型一致: 是否与架构定义一致？
3. 功能覆盖完整: 是否覆盖所有产品功能？

【视角5：API 测试用例评审】
【视角6：前端测试用例评审】
【视角7：后端测试用例评审】

请将评审问题输出到 IMPLEMENTATION_REVIEW.md 文档。
```

### 按模块设计评审（大项目）

```
请阅读以下文档进行模块详细设计评审：
- ARCHITECTURE.md：架构概要和技术栈
- PRODUCT-DESIGN-{ModuleName}.md：模块产品功能需求
- [如有上游依赖] API-SPEC-{upstream-M}.md：上游模块接口规范
- API-SPEC-{ModuleName}.md：模块接口详细规范
- TEST-CASES-{ModuleName}-API.md：模块 API 测试用例
- BACKEND-DESIGN-{ModuleName}.md：模块后端详细设计
- TEST-CASES-{ModuleName}-BACKEND.md：模块后端测试用例
- FRONTEND-DESIGN-{ModuleName}.md：模块前端详细设计
- TEST-CASES-{ModuleName}-FRONTEND.md：模块前端测试用例

评审标准（八视角）：

【视角1-7：同整体评审】

【视角8：跨模块接口一致性评审】
1. 上游接口调用一致: 本模块调用上游接口是否与 API-SPEC-{upstream-M}.md 一致？
2. 数据结构一致: 使用上游模块的数据结构是否与上游定义一致？
3. 依赖完整性: 上游接口依赖是否都已明确列出？

请将评审问题输出到 IMPLEMENTATION-{M}_REVIEW.md 文档。
```
