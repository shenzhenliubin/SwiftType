# E2E Tester - 评审回应阶段

> 本阶段回应 E2E Reviewer 对测试设计方案的评审意见，不涉及测试执行。

## 输入文档

- **E2E-REVIEW.md**: E2E Reviewer 对测试设计的评审意见
- **E2E-TEST-CASES.md**: 当前 E2E 测试用例文档
- **E2E test code**: 当前 E2E 测试代码
- **PRODUCT-DESIGN.md**: 产品功能定义（用于对照验证）
- **UI-DESIGN.md/.pen**: 界面设计稿（用于对照验证）

## 输出文档

- **E2E-REVIEW-FEEDBACK.md**: 对评审意见的反馈
- **修改后的测试代码**: 根据评审要求修改的测试代码（如有）
- **修改后的 E2E-TEST-CASES.md**: 根据评审要求修改的测试用例（如有）

## 工作流程

### Step 1: 阅读评审文档

1. 阅读 E2E-REVIEW.md
2. 理解每个评审问题的维度和具体建议
3. 按维度分类评审问题

### Step 2: 逐一回应评审问题

对于每个评审问题，判断：

```
1. 接受修改:
   - 按评审要求修改测试用例文档或测试代码
   - 在反馈文档中记录"已修改"

2. 拒绝修改:
   - 提出拒绝理由
   - 例如: 与 PRODUCT-DESIGN.md 用户流程定义不一致、测试场景不符合实际使用等
   - 在反馈文档中记录拒绝理由

3. 需要澄清:
   - 如果评审问题与 PRODUCT-DESIGN.md 有矛盾
   - 如果评审要求超出 E2E 测试范围（如要求做性能测试、单元测试等）
   - 输出 DOCUMENT_CONFLICT.md，请求人工介入
```

### Step 3: 修改测试设计

如果接受了评审问题：

1. 修改测试用例文档（E2E-TEST-CASES.md）或测试代码
2. 确保修改后的测试用例和代码仍然一致

> 注意：本阶段只修改测试设计，不执行测试。执行在 test-execution-phase 进行。

### Step 4: 输出反馈文档

输出 E2E-REVIEW-FEEDBACK.md。

## 提示词样例

```
你需要阅读当前项目目录下的 E2E-REVIEW.md 文档，这是 E2E Reviewer 对你测试设计方案的评审意见。

请逐一审阅每个问题:

1. 如果接受评审问题:
   - 按评审要求修改测试用例或测试代码
   - 在反馈文档中记录"已修改"

2. 如果不接受评审问题:
   - 提出拒绝理由
   - 例如: 与 PRODUCT-DESIGN.md 用户流程定义不一致、超出 E2E 测试范围
   - 在反馈文档中记录拒绝理由

3. 如果评审问题与设计文档有矛盾:
   - 输出 DOCUMENT_CONFLICT.md，请求人工介入

注意：本阶段只修改测试设计方案，不执行测试。

请将反馈输出到 E2E-REVIEW-FEEDBACK.md 文档。
```
