# E2E Tester - 测试设计阶段

## 输入文档（阅读所有已确定的产出物）

### 小项目

**产品设计阶段文档**:
- PRODUCT-DESIGN.md：产品功能定义（用户流程、功能规格）—— **测试用例设计的主要依据**
- UI-DESIGN.md/.pen：界面设计稿（页面元素、交互细节、视觉参考）

**技术架构阶段文档**:
- ARCHITECTURE.md：技术架构（前端技术栈、部署地址、环境信息）
- API-SPEC.md：接口规范（测试需要构造数据时参考）

**业务需求阶段文档**:
- BRD.md：业务需求文档（补充核心场景理解）

### 大项目

**产品设计阶段文档**:
- PRODUCT-DESIGN-HIGH-LEVEL.md：高层产品设计（模块划分、整体流程）
- PRODUCT-DESIGN-{M}.md：各模块产品功能定义
- UI-STYLE-GUIDE.md/.pen：整体风格指南
- UI-DESIGN-{M}.md/.pen：各模块界面设计稿

**技术架构阶段文档**:
- ARCHITECTURE.md：技术架构
- API-SPEC-{M}.md：各模块接口规范

**业务需求阶段文档**:
- BRD.md：业务需求文档

**批准文档**:
- 所有任务单元的 CODING_APPROVE.md：确认所有代码已通过评审

**关键原则**:
> 测试用例基于 PRODUCT-DESIGN.md 中定义的用户流程设计。
> 对照 UI-DESIGN.md 的交互设计确定页面操作细节。
> 本阶段只设计测试用例和编写测试代码，不执行测试。

## 输出文档

- **E2E-TEST-CASES.md**：E2E 测试用例文档（基于用户流程设计）
- **E2E test code**：浏览器自动化测试代码

## 工作流程

### Step 1: 梳理用户流程

**小项目**:
1. 阅读 PRODUCT-DESIGN.md，提取所有**用户流程**（用户从进入系统到完成目标的操作路径）
2. 阅读 UI-DESIGN.md，补充每个流程涉及的页面和交互细节
3. 阅读 BRD.md，理解核心业务场景背景

**大项目**:
1. 阅读 PRODUCT-DESIGN-HIGH-LEVEL.md 了解整体模块划分和跨模块流程，再阅读各 PRODUCT-DESIGN-{M}.md 提取所有**用户流程**
2. 阅读 UI-STYLE-GUIDE.md 了解整体视觉规范，再阅读各 UI-DESIGN-{M}.md 补充每个流程涉及的页面和交互细节
3. 阅读 BRD.md，理解核心业务场景背景

```
用户流程提取示例:
- 注册流程: 首页 → 注册页 → 填写信息 → 提交 → 注册成功
- 登录流程: 登录页 → 输入账号密码 → 提交 → 进入主页
- 核心业务流程: 登录 → 浏览内容 → 选择操作 → 确认 → 查看结果
```

### Step 2: 设计 E2E 测试用例

根据用户流程设计测试用例，每个用户流程至少覆盖：

**小项目**:

| 用例类型 | 说明 | 依据文档 |
|---------|------|---------|
| **主流程（Happy Path）** | 用户正常操作完成目标 | PRODUCT-DESIGN.md 的流程定义 |
| **异常流程** | 用户操作出错时的系统反馈 | PRODUCT-DESIGN.md 的交互规则 |
| **页面导航** | 页面间跳转和返回 | UI-DESIGN.md 的页面结构 |

**大项目**:

| 用例类型 | 说明 | 依据文档 |
|---------|------|---------|
| **主流程（Happy Path）** | 用户正常操作完成目标 | PRODUCT-DESIGN-{M}.md 的流程定义 |
| **异常流程** | 用户操作出错时的系统反馈 | PRODUCT-DESIGN-{M}.md 的交互规则 |
| **页面导航** | 页面间跳转和返回 | UI-DESIGN-{M}.md 的页面结构 |
| **跨模块集成** | 涉及多个模块协作的端到端流程 | PRODUCT-DESIGN-HIGH-LEVEL.md 的整体流程 |

输出 E2E-TEST-CASES.md。

### Step 3: 编写浏览器自动化测试代码

1. 根据 ARCHITECTURE.md 确认前端技术栈，选择对应的 E2E 测试框架
2. 根据 E2E-TEST-CASES.md 编写浏览器自动化测试代码
3. **大项目**: 参考 API-SPEC-{M}.md 了解各模块接口，用于构造测试数据和验证跨模块交互

```
编写原则:
- 每个测试用例对应一个独立的测试函数
- 使用显式等待，不使用固定 sleep
- 页面元素定位优先使用 data-testid，其次使用语义化选择器
- 每个测试包含: 准备数据 → 执行操作 → 验证结果
- 测试之间相互独立，不依赖执行顺序
```

### Step 4: 输出测试设计文档

确认以下内容已输出：
- E2E-TEST-CASES.md（测试用例文档，含覆盖度矩阵）
- E2E test code（浏览器自动化测试代码）

等待 E2E Reviewer 评审测试设计。
