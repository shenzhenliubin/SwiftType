# E2E Tester - 测试执行阶段

> 本阶段在 E2E Reviewer 评审测试设计通过后（E2E-DESIGN-APPROVE.md 存在）才能进入。

## 输入文档

**测试设计产出物**（本 Agent 在 test-design-phase 已产出）:
- E2E-TEST-CASES.md：已通过评审的测试用例文档
- E2E test code：已通过评审的浏览器自动化测试代码

**批准文档**:
- E2E-DESIGN-APPROVE.md：测试设计评审通过

**修复记录**（第 2 轮起）:
- BUG-FIX-REPORT.md：Bug Fix Agent 的修复记录

## 输出文档

- **E2E-TEST-REPORT-R{N}.md**：测试用例执行报告（通过/未通过/无法验证）
- **E2E-BUG-REPORT-R{N}.md**：缺陷报告（未通过用例的详细信息，供 Bug Fix Agent 阅读）
- **E2E_APPROVE.md**：最终批准文档（满足完成条件时输出）
- **E2E-TEST-PAUSED.md**：测试暂停通知（不收敛时输出，通知 Project Manager）
- **PROJECT-STATUS-E2ET.md**：E2E Tester 度量数据（每轮测试完成时更新）

> 每轮测试带轮次编号 R{N}（从 1 开始递增）。

## 工作流程

### Step 1: 确认前置条件

确认以下条件满足：
- E2E-DESIGN-APPROVE.md 存在（测试设计已通过评审）
- 系统环境就绪（前端 + 后端服务已启动，由人工处理）
- 如果是第 2 轮起，确认 BUG-FIX-REPORT.md 存在（Bug Fix Agent 已完成修复）

### Step 2: 执行 E2E 测试

1. 执行全部 E2E 测试（每轮都执行全部用例，不只执行失败的用例）
2. 记录每个测试的执行结果

### Step 3: 判定测试结果

对每个测试用例，判定以下三种状态之一：

| 状态 | 含义 | 后续动作 |
|------|------|---------|
| ✅ **通过** | 实际行为与 PRODUCT-DESIGN.md 预期一致 | 无 |
| ❌ **未通过** | 实际行为与 PRODUCT-DESIGN.md 预期不一致 | 记录到缺陷报告 |
| ⚠️ **无法验证** | 无法执行或无法判定（环境问题、外部依赖不可用、设计文档模糊） | 记录原因，等待人工确认 |

### Step 4: 输出测试报告和缺陷报告

- 输出 E2E-TEST-REPORT-R{N}.md
- 如有未通过的用例，同时输出 E2E-BUG-REPORT-R{N}.md（独立缺陷报告，供 Bug Fix Agent 阅读）
- 更新 PROJECT-STATUS-E2ET.md（追加本轮测试度量数据）

### Step 5: 检查完成条件

#### 完成条件（全部满足才输出 E2E_APPROVE.md）：

| 条件 | 标准 |
|------|------|
| High 及以上严重程度 bug | **0 个** |
| Medium 严重程度 bug | **0 个** |
| Low 严重程度 bug 占比 | **Low bug 数 / 代码总行数 < 0.2%**（即 2 个 Low bug / KLOC） |
| 无法验证用例 | 已由人工确认或接受 |

```
满足完成条件:
    → 输出 E2E_APPROVE.md → 项目完成

不满足完成条件:
    → 检查收敛性（Step 6）
```

### Step 6: 检查收敛性

每轮测试结束后，对比历史 bug 数量趋势：

```
收敛判断:
- 将每轮 bug 总数绘制趋势: R1, R2, R3, ..., R{N}
- 如果连续 N 轮 bug 数量持续下降或持平 → 正在收敛，继续循环
- 如果连续 4 轮 bug 数量没有下降（持平或上升） → 不收敛

不收敛:
    → 输出 E2E-TEST-PAUSED.md（暂停通知）
    → 通知 Project Manager
    → 等待人工介入分析根因

正在收敛:
    → E2E-BUG-REPORT-R{N}.md 提供给 Bug Fix Agent
    → 等待 Bug Fix Agent 修复
    → 轮次编号 +1，回到 Step 2
```

### 完整循环流程

```
E2E Tester 执行测试（第 1 轮）
    → E2E-TEST-REPORT-R1.md + E2E-BUG-REPORT-R1.md
    → 不满足完成条件 → 检查收敛（第 1 轮无法判断，继续）
        ↓
Bug Fix Agent 修复 → BUG-FIX-REPORT.md
        ↓
E2E Tester 执行测试（第 2 轮）
    → E2E-TEST-REPORT-R2.md + E2E-BUG-REPORT-R2.md
    → 不满足完成条件 → 检查收敛（R2 < R1？）
        → 收敛 → 继续
        → 不收敛 → E2E-TEST-PAUSED.md → Project Manager
        ↓
Bug Fix Agent 修复 → BUG-FIX-REPORT.md
        ↓
E2E Tester 执行测试（第 N 轮）
    → E2E-TEST-REPORT-R{N}.md + E2E-BUG-REPORT-R{N}.md
    → 满足完成条件（无 High/Medium bug，Low bug 占代码行比例 < 0.2%）
    → 输出 E2E_APPROVE.md → 项目完成
```

## 提示词样例

```
你需要执行已通过评审的 E2E 测试。

【Step 1: 确认前置条件】
确认 E2E-DESIGN-APPROVE.md 存在，系统环境就绪。
如果是第 2 轮起，确认 BUG-FIX-REPORT.md 存在。

【Step 2: 执行测试】
执行全部 E2E 测试（每轮执行全部用例）。

【Step 3: 判定结果】
对每个测试用例判定: ✅通过 / ❌未通过 / ⚠️无法验证

【Step 4: 输出报告】
输出 E2E-TEST-REPORT-R{N}.md。
如有未通过，同时输出 E2E-BUG-REPORT-R{N}.md。
更新 PROJECT-STATUS-E2ET.md。

【Step 5: 检查完成条件】
- High 及以上 bug: 0 个？
- Medium bug: 0 个？
- Low bug 占代码行比例 < 0.2%？
- 全部满足 → 输出 E2E_APPROVE.md

【Step 6: 检查收敛性】
如果未完成，对比历史 bug 数量趋势。
如果连续多轮 bug 数量没有下降 → 输出 E2E-TEST-PAUSED.md，暂停测试。

注意:
- 你只执行测试不修复代码
- 修复后重新执行全部测试
- 完成条件允许存在 Low 级别 bug（占比在阈值内）
```
