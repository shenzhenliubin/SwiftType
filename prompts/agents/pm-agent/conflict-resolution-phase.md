# Project Manager - 矛盾处理阶段

> 本阶段处理项目中出现的文档矛盾和异常情况。Project Manager 不自行解决矛盾，而是向人类发出介入信号。

## 输入文档

- **DOCUMENT_CONFLICT.md**: 任意 Agent 报告的文档矛盾
- **E2E-TEST-PAUSED.md**: E2E Tester 报告的测试不收敛
- **REVIEW_PAUSED.md**: 任意 Reviewer 评审暂停（评审对象指出设计文档矛盾）
- **Bug Fix Agent 反馈**: 缺陷根因是设计文档问题

## 输出文档

- **DOCUMENT_CONFLICTS.md**: 文档矛盾持久化记录（追加）
- **PROJECT-STATUS.md**: 更新项目状态（标记暂停）

## 工作流程

### Step 1: 接收矛盾/异常信号

从以下来源接收信号：

| 信号来源 | 信号文档 | 含义 |
|---------|---------|------|
| 任意 Agent | DOCUMENT_CONFLICT.md | 发现文档间矛盾 |
| E2E Tester | E2E-TEST-PAUSED.md | 测试不收敛，连续 4 轮无改善 |
| Code Reviewer / E2E Reviewer | REVIEW_PAUSED.md | 评审中发现设计文档矛盾，暂停评审 |
| Bug Fix Agent | 在 BUG-FIX-REPORT.md 中标记 | 缺陷根因是设计文档问题 |

### Step 2: 持久化矛盾信息

将矛盾信息追加到 DOCUMENT_CONFLICTS.md：

```
- 矛盾发现者
- 矛盾类型
- 涉及的文档和具体内容
- 矛盾描述
- 影响范围（哪些流程受影响）
```

### Step 3: 暂停受影响的流程

根据矛盾的影响范围：

| 矛盾类型 | 暂停范围 |
|---------|---------|
| 需求与设计矛盾 | 暂停依赖该需求的所有下游流程 |
| 设计文档间矛盾 | 暂停依赖这些文档的下游流程 |
| 接口定义矛盾 | 暂停编码和测试 |
| 测试不收敛 | 暂停 E2E 测试循环 |
| 设计文档本身有问题 | 暂停 Bug Fix，等待设计修复 |

### Step 4: 向人类发出介入信号

通知人类介入，提供以下信息：

1. 矛盾的详细描述
2. 涉及的文档和 Agent
3. 建议的分析方向
4. 当前暂停的流程范围

### Step 5: 等待人类决策

等待人类处理后：
- 人类修改了相关文档 → 通知受影响的 Agent 重新阅读文档，恢复流程
- 人类做出决策 → 按决策执行，恢复流程
- 人类要求回退 → 回退到指定阶段

### 完整流程

```
收到矛盾/异常信号
    ↓
持久化到 DOCUMENT_CONFLICTS.md
    ↓
暂停受影响的流程
    ↓
向人类发出介入信号
    ↓
等待人类决策
    ↓
根据决策恢复流程 → 回到 stage-transition-phase
```

## 提示词样例

```
你收到了一个矛盾/异常信号。

请处理:

1. 将矛盾信息持久化到 DOCUMENT_CONFLICTS.md:
   - 发现者、矛盾类型、涉及文档、矛盾描述、影响范围

2. 暂停受影响的流程:
   - 根据矛盾类型确定暂停范围

3. 向人类发出介入信号:
   - 描述矛盾详情
   - 说明暂停范围
   - 建议分析方向

4. 等待人类决策后恢复流程。

注意:
- 你不自行解决矛盾，只负责持久化和通知
- 矛盾解决后，通知相关 Agent 重新阅读修改后的文档
```
