# Project Manager - 项目完成阶段

> 本阶段在收到 E2E_APPROVE.md 后触发，标志项目开发完成。

## 输入文档

- **E2E_APPROVE.md**: E2E 测试通过文档
- **PROJECT-STATUS.md**: 项目全程状态记录
- 各阶段的关键产出物（用于总结）

## 输出文档

- **PROJECT-COMPLETE.md**: 项目完成总结

## 工作流程

### Step 1: 确认项目完成条件

确认以下条件全部满足：

| 条件 | 验证方式 |
|------|---------|
| E2E_APPROVE.md 存在 | 文件存在检查 |
| 无未处理的文档矛盾 | DOCUMENT_CONFLICTS.md 中无"待处理"项 |
| 无暂停的流程 | 无 E2E-TEST-PAUSED.md |

### Step 2: 收集项目信息

收集以下信息用于项目总结：

1. **项目基本信息**: 项目名称、启动日期、完成日期
2. **项目模式**: 完整设计 / 模块拆分设计
3. **各阶段完成情况**: 每个阶段的通过轮次、主要讨论事项
4. **模块完成情况**（大项目）: 各模块的设计和 review 情况
5. **代码统计**: 任务单元数、代码行数
6. **E2E 测试情况**: 测试轮次、bug 趋势、最终状态
7. **矛盾记录**: 出现过哪些文档矛盾、如何解决的

### Step 3: 输出项目完成总结

输出 PROJECT-COMPLETE.md。

### 完整流程

```
收到 E2E_APPROVE.md
    ↓
确认项目完成条件
    ↓
收集项目全程信息
    ↓
输出 PROJECT-COMPLETE.md
    ↓
项目结束
```

## 提示词样例

```
项目已完成。E2E_APPROVE.md 已存在。

请输出项目完成总结:

1. 确认完成条件:
   - E2E_APPROVE.md 存在
   - 无未处理的矛盾
   - 无暂停的流程

2. 收集项目信息:
   - 各阶段完成情况
   - E2E 测试情况（轮次、bug 趋势）
   - 出现过的矛盾及解决方式

3. 输出 PROJECT-COMPLETE.md。

注意:
- 总结应客观反映项目全程
- 记录关键决策和转折点
```
