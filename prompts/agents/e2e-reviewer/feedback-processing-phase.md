# E2E Reviewer - 反馈处理阶段

## 输入文档

- **E2E-REVIEW-FEEDBACK.md**: E2E Tester 对评审问题的反馈
- **修改后的 E2E-TEST-CASES.md**: 根据评审要求修改的测试用例（如有）
- **修改后的 E2E test code**: 根据评审要求修改的测试代码（如有）

## 输出文档

- **E2E-DESIGN-APPROVE.md**: 测试设计批准文档（全部达成一致时，E2E Tester 可进入执行阶段）
- **E2E-REVIEW-FEEDBACK-RESPONSE-{n}.md**: 继续追问文档（仍有问题时）
- **PROJECT-STATUS-E2ER.md**: E2ER 评审度量数据（评审通过时写入/更新）

## 工作流程

### Step 1: 阅读 E2E Tester 的反馈

1. 阅读 E2E-REVIEW-FEEDBACK.md
2. 逐一审阅每个评审问题的反馈

### Step 2: 评估反馈

对每个问题，判断：

```
1. 接受修改:
   - E2E Tester 已按评审要求修改测试用例或测试代码
   - 确认修改是否解决了评审问题
   - 记录确认

2. 接受拒绝:
   - E2E Tester 的拒绝理由合理
   - 撤回该问题

3. 继续追问:
   - 不接受拒绝理由
   - 继续提出你的理由

4. 需要人工介入:
   - E2E Tester 指出设计文档矛盾
   - 暂停评审，请求人工介入
```

### Step 3: 检查修改后的测试设计

如果 E2E Tester 修改了测试用例或测试代码：

1. 检查修改后的 E2E-TEST-CASES.md 是否解决了覆盖度和质量问题
2. 检查修改后的测试代码是否与更新后的用例文档一致
3. 确认修改是否引入了新的问题

### Step 4: 输出处理结果

```
全部达成一致 → 输出 E2E-DESIGN-APPROVE.md → E2E Tester 可进入测试执行阶段
仍有问题 → 输出 E2E-REVIEW-FEEDBACK-RESPONSE-1.md（编号递增）
需人工介入 → 输出 REVIEW_PAUSED.md，请求人工介入
```

## 提示词样例

```
你需要阅读当前项目目录下的 E2E-REVIEW-FEEDBACK.md 文档，这是 E2E Tester 对你评审问题的回复。

请逐一审阅每个问题的反馈:

1. 如果 E2E Tester 已接受问题:
   - 确认是否已修改测试用例或测试代码
   - 确认修改是否解决了评审问题
   - 确认修改是否引入新的问题

2. 如果 E2E Tester 不接受问题:
   - 审阅其拒绝理由
   - 如果拒绝理由合理，撤回该问题
   - 如果不接受其拒绝理由，继续提出你的理由

3. 如果 E2E Tester 指出设计文档矛盾:
   - 输出 REVIEW_PAUSED.md，暂停评审
   - 请求人工介入

处理结果:
- 如果所有问题已达成一致，生成 E2E-DESIGN-APPROVE.md（测试设计批准，E2E Tester 可进入执行阶段）
- 如果仍有未解决问题，生成 E2E-REVIEW-FEEDBACK-RESPONSE-1.md
- 如果需人工介入，输出 REVIEW_PAUSED.md

只有当所有问题都达成一致，才输出 E2E-DESIGN-APPROVE.md。

通过后，请更新 PROJECT-STATUS-E2ER.md，记录 E2E 测试设计评审的度量数据。
```
