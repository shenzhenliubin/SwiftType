# UI Reviewer - 评审阶段

> 本阶段支持三种评审场景：完整 UI 设计评审（小项目）、风格指南评审（大项目）、模块 UI 设计评审（大项目）。

## 输入文档

### 场景 1: 完整 UI 设计评审（小项目）

- **UI-DESIGN.md**: 界面设计说明文档
- **UI-DESIGN.pen**: 高保真设计文件
- **DEMO.md**: 交互 Demo 说明文档
- **DEMO.pen**: 可点击原型文件
- **PRODUCT-DESIGN.md**: 产品设计文档（用于验证产品意图符合度）

### 场景 2: 风格指南评审（大项目）

- **UI-STYLE-GUIDE.md**: 整体风格指南说明文档
- **UI-STYLE-GUIDE.pen**: 整体风格指南设计文件
- **PRODUCT-DESIGN-HIGH-LEVEL.md**: 高层产品设计
- **PRODUCT-DESIGN-{M}.md**: 各模块产品设计文档

### 场景 3: 模块 UI 设计评审（大项目）

- **UI-DESIGN-{M}.md**: 模块界面设计说明文档
- **UI-DESIGN-{M}.pen**: 模块高保真设计文件
- **DEMO-{M}.md**: 模块交互 Demo 说明文档
- **DEMO-{M}.pen**: 模块可点击原型文件
- **UI-STYLE-GUIDE.md**: 整体风格指南（验证遵循度）
- **PRODUCT-DESIGN-{M}.md**: 模块产品设计文档

## 输出文档

| 场景 | 输出文档 |
|------|---------|
| 完整评审 | UI-DESIGN_REVIEW.md |
| 风格指南评审 | UI-STYLE-GUIDE_REVIEW.md |
| 模块评审 | UI-DESIGN-{M}_REVIEW.md |

**零问题直接通过规则**:
> 如果评审过程中未发现任何问题，根据评审场景直接输出对应的 APPROVE 文档（UI-DESIGN_APPROVE.md / UI-STYLE-GUIDE_APPROVE.md / UI-DESIGN-{M}_APPROVE.md），不输出 REVIEW 文档。
> 只有存在问题时才输出 REVIEW 文档并进入评审回应流程。

## 评审标准

### 通用评审维度（所有场景适用）

#### 视角1：产品意图符合度

| 评审维度 | 评审要点 |
|---------|---------|
| **功能表达准确性** | UI 是否准确表达了每个功能的意图？ |
| **流程呈现完整性** | 用户流程在 UI 中是否被正确呈现？ |
| **交互规则实现** | PRODUCT-DESIGN 中定义的交互规则是否在 UI 中正确实现？ |
| **页面覆盖完整性** | 所有产品设计定义的页面是否都有对应的 UI 设计？ |

#### 视角2：美学质量评审

| 评审维度 | 评审要点 |
|---------|---------|
| **视觉美学** | 配色是否协调？布局是否美观？整体风格是否统一？ |
| **视觉层级** | 信息优先级是否清晰？视觉焦点是否正确？关键信息是否突出？ |

#### 视角3：风格一致性评审

| 评审维度 | 评审要点 |
|---------|---------|
| **整体视觉风格** | 整体视觉风格是否统一（扁平/立体/渐变等风格）？ |
| **图标风格一致性** | 图标风格是否统一（线性/填充/双色等）？图标尺寸是否一致？ |
| **按钮样式一致性** | 按钮样式是否统一（圆角/阴影/边框等）？按钮状态（正常/悬停/点击/禁用）是否一致？ |
| **容器样式一致性** | 卡片/容器样式是否统一（圆角/阴影/边框等）？ |

#### 视角4：交互一致性评审

| 评审维度 | 评审要点 |
|---------|---------|
| **组件交互行为** | 同类组件交互行为是否一致（如按钮点击反馈、输入框聚焦样式）？ |
| **表单验证提示** | 表单验证提示方式是否一致（提示位置、提示样式、成功/错误状态）？ |
| **加载状态展示** | 加载状态展示方式是否一致（Loading动画、进度条、骨架屏）？ |
| **错误提示展示** | 错误提示展示方式是否一致（Toast/弹窗/内联提示）？错误提示样式是否统一？ |

### 风格指南特有评审维度（场景 2 额外）

| 评审维度 | 评审要点 |
|---------|---------|
| **规范覆盖完整性** | 风格指南是否覆盖所有模块需要的 UI 元素（配色、字体、间距、组件）？ |
| **各模块适用性** | 风格指南的规范是否适用于每个模块的页面需求？ |
| **组件库完整性** | 通用组件库是否包含所有模块共享的组件？ |
| **可扩展性** | 风格指南是否支持模块特有的 UI 需求扩展？ |
| **配色方案合理性** | 配色方案是否考虑了所有模块的场景（警示、成功、错误等）？ |
| **间距规范合理性** | 间距规范是否能满足不同复杂度页面的布局需求？ |

### 模块 UI 特有评审维度（场景 3 额外）

| 评审维度 | 评审要点 |
|---------|---------|
| **风格指南遵循度** | 模块 UI 是否严格遵循 UI-STYLE-GUIDE.md 的规范？ |
| **配色一致性** | 模块使用的配色是否与风格指南定义一致？ |
| **字体一致性** | 模块使用的字号、字重是否与风格指南定义一致？ |
| **间距一致性** | 模块使用的间距是否与风格指南定义一致？ |
| **组件一致性** | 模块使用的通用组件样式是否与风格指南定义一致？ |
| **跨模块交互** | 与其他模块的页面跳转是否合理？ |

## 工作流程

### 场景 1: 完整 UI 设计评审（小项目）

1. 阅读 PRODUCT-DESIGN.md，理解产品设计意图
2. 阅读 UI-DESIGN.md，查看 UI-DESIGN.pen 设计稿
3. 从产品意图视角评审：验证功能表达、流程呈现、交互规则
4. 从美学质量视角评审：评估视觉美学、视觉层级
5. 从风格一致性视角评审：验证整体风格、图标、按钮、容器样式统一性
6. 从交互一致性视角评审：验证组件交互、表单提示、加载状态、错误提示统一性
7. 输出 UI-DESIGN_REVIEW.md，等待 UI Designer 回应

### 场景 2: 风格指南评审（大项目）

1. 阅读 PRODUCT-DESIGN-HIGH-LEVEL.md 和所有 PRODUCT-DESIGN-{M}.md
2. 阅读 UI-STYLE-GUIDE.md，查看 UI-STYLE-GUIDE.pen
3. 从美学质量视角评审
4. 从风格指南特有维度评审：验证规范覆盖完整性、各模块适用性、组件库完整性
5. 逐模块验证风格指南是否能满足该模块的 UI 需求
6. 输出 UI-STYLE-GUIDE_REVIEW.md，等待 UI Designer 回应

### 场景 3: 模块 UI 设计评审（大项目）

1. 阅读 PRODUCT-DESIGN-{M}.md，理解模块产品设计意图
2. 阅读 UI-STYLE-GUIDE.md，了解整体视觉规范
3. 阅读 UI-DESIGN-{M}.md，查看 UI-DESIGN-{M}.pen 设计稿
4. 从产品意图视角评审：验证模块功能表达
5. 从美学质量视角评审
6. 从模块 UI 特有维度评审：验证风格指南遵循度（配色、字体、间距、组件一致性）
7. 检查跨模块交互是否合理
8. 输出 UI-DESIGN-{M}_REVIEW.md，等待 UI Designer 回应

## 提示词样例

### 完整 UI 设计评审（小项目）

```
请阅读当前项目目录下的以下文档进行界面设计评审：
- PRODUCT-DESIGN.md：产品设计文档
- UI-DESIGN.md：界面设计说明
- UI-DESIGN.pen：高保真设计文件
- DEMO.md：交互 Demo 说明

评审标准（四视角）:

【视角1：产品意图符合度】
1. 功能表达准确性: UI 是否准确表达了每个功能的意图？
2. 流程呈现完整性: 用户流程是否被正确呈现？
3. 交互规则实现: 交互规则是否被正确实现？
4. 页面覆盖完整性: 所有页面是否都有 UI 设计？

【视角2：美学质量评审】
1. 视觉美学: 配色是否协调？布局是否美观？
2. 视觉层级: 信息优先级是否清晰？视觉焦点是否正确？

【视角3：风格一致性评审】
1. 整体视觉风格: 整体风格是否统一（扁平/立体/渐变）？
2. 图标风格一致性: 图标风格、尺寸是否统一？
3. 按钮样式一致性: 按钮样式、状态是否统一？
4. 容器样式一致性: 卡片/容器样式是否统一？

【视角4：交互一致性评审】
```
