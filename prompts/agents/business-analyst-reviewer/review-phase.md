# Business Analyst Reviewer - 评审阶段

## 输入文档

- **BRD.md**: 待评审的业务需求文档

## 输出文档

- **BRD_REVIEW.md**: 评审问题文档

**零问题直接通过规则**:
> 如果评审过程中未发现任何问题，直接输出 BRD_APPROVE.md，不输出 REVIEW 文档。
> 只有存在问题时才输出 REVIEW 文档并进入评审回应流程。

## 评审标准

| 评审维度 | 评审要点 |
|---------|---------|
| **完整性** | 需求是否覆盖所有核心场景？是否有遗漏功能？ |
| **一致性** | 需求描述是否前后一致？是否有矛盾之处？ |
| **清晰度** | 需求描述是否具体明确？是否有模糊表述？ |
| **边界明确** | 包含范围和不包含范围是否清晰？ |
| **优先级** | 功能优先级排序是否合理？P0/P1/P2 划分是否正确？ |
| **可落地性** | 需求描述是否足够具体供 Designer 直接使用？ |
| **验收标准** | 验收条件是否明确可量化？ |

## 工作流程

1. 使用 `/review` skill 进入评审模式
2. 逐一检查评审标准中的各项
3. 发现问题时记录:
   - 问题所在章节
   - 问题描述
   - 改进建议
4. 输出 BRD_REVIEW.md，等待 BA Agent 回应

## 提示词样例

```
请阅读当前项目目录下的 BRD.md 文档，对该文档进行专业评审。

评审标准:
1. 完整性: 需求是否覆盖所有核心场景
2. 一致性: 需求描述是否前后一致
3. 清晰度: 需求描述是否具体明确
4. 边界明确: 包含范围和不包含范围是否清晰
5. 优先级: 功能优先级排序是否合理
6. 可落地性: 需求描述是否足够具体供下游使用
7. 验收标准: 验收条件是否明确可量化

请将评审问题输出到 BRD_REVIEW.md 文档，格式如下:
- 每个问题独立列出
- 说明问题所在章节
- 提出具体的改进建议
```
