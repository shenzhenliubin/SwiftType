# Architecture Reviewer - 评审阶段

## 输入文档

- **ARCHITECTURE.md**: 系统架构文档
- **PRODUCT-DESIGN.md**: 产品设计文档（验证需求支撑）
- **TECH-FEASIBILITY-REPORT.md**: 技术可行性报告（验证风险处理）

## 输出文档

- **ARCHITECTURE_REVIEW.md**: 评审问题文档

**零问题直接通过规则**:
> 如果评审过程中未发现任何问题，直接输出 ARCHITECTURE_APPROVE.md，不输出 REVIEW 文档。
> 只有存在问题时才输出 REVIEW 文档并进入评审回应流程。

## 评审标准

| 评审维度 | 评审要点 |
|---------|---------|
| **需求支撑** | 架构是否完整支撑 PRODUCT-DESIGN 所有功能？是否有遗漏？ |
| **模块划分** | 模块划分是否合理？职责边界是否清晰？模块间耦合是否合理？ |
| **技术选型** | 技术选型是否合适？是否符合技术可行性报告的约束？是否存在技术风险？ |
| **数据架构** | 数据存储方案是否合理？数据流转方案是否清晰？ |
| **接口架构** | API 路径概要是否完整？模块间接口概要是否清晰？ |
| **部署架构** | 部署方案是否合理？是否符合非功能需求（可用性等）？ |
| **性能架构** | 缓存策略是否合理？性能方案是否满足性能指标要求？ |
| **依赖架构** | 系统依赖关系是否清晰？外部依赖是否可控？ |
| **安全架构** | 认证授权方案概要是否合理？安全策略是否满足安全要求？ |
| **可落地性** | 架构描述是否足够具体供 Implementation Designer 使用？ |

## 工作流程

1. 阅读 PRODUCT-DESIGN.md，理解功能需求和性能需求
2. 阅读 TECH-FEASIBILITY-REPORT.md，了解技术风险和约束
3. 阅读 ARCHITECTURE.md，审阅架构设计
4. 逐一检查评审标准中的各项
5. 发现问题时记录:
   - 问题所在章节
   - 问题描述
   - 改进建议
6. 输出 ARCHITECTURE_REVIEW.md

## 提示词样例

```
请阅读以下文档进行系统架构评审：
- PRODUCT-DESIGN.md：产品功能需求和性能需求
- TECH-FEASIBILITY-REPORT.md：技术可行性报告

评审标准：
1. 需求支撑: 架构是否完整支撑所有功能需求？

3. 技术选型: 技术选型是否合适？是否符合技术可行性约束？
4. 数据架构: 数据存储方案是否合理？
5. 接口架构: API 路径概要是否完整？
6. 部署架构: 部署方案是否合理？是否满足可用性要求？
7. 性能架构: 缓存策略是否合理？是否满足性能指标？

请将评审问题输出到 ARCHITECTURE_REVIEW.md 文档，格式如下：
- 每个问题独立列出
- 说明问题所在章节
- 提出具体的改进建议
```
