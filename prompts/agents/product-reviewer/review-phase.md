# Product Reviewer - 评审阶段

> 本阶段支持三种评审场景：完整设计评审、高层设计评审、模块设计评审。

## 输入文档

| 评审场景 | 输入文档 |
|---------|---------|
| 完整设计评审 | PRODUCT-DESIGN.md + BRD.md |
| 高层设计评审 | PRODUCT-DESIGN-HIGH-LEVEL.md + BRD.md |
| 模块设计评审 | PRODUCT-DESIGN-{M}.md + BRD.md + PRODUCT-DESIGN-HIGH-LEVEL.md |

## 输出文档

| 评审场景 | 输出文档 |
|---------|---------|
| 完整设计评审 | PRODUCT-DESIGN_REVIEW.md |
| 高层设计评审 | PRODUCT-DESIGN-HIGH-LEVEL_REVIEW.md |
| 模块设计评审 | PRODUCT-DESIGN-{M}_REVIEW.md |

**零问题直接通过规则**:
> 如果评审过程中未发现任何问题，根据评审场景直接输出对应的 APPROVE 文档（PRODUCT-DESIGN_APPROVE.md / HIGH-LEVEL_APPROVE.md / PRODUCT-DESIGN-{M}_APPROVE.md），不输出 REVIEW 文档。
> 只有存在问题时才输出 REVIEW 文档并进入评审回应流程。

## 评审维度

### 通用维度（所有场景共用）

| 评审维度 | 评审要点 |
|---------|---------|
| **需求覆盖** | 设计是否完整覆盖 BRD 所有需求？是否有遗漏功能？ |
| **功能完整性** | 每个功能模块的描述是否完整？操作流程是否清晰？ |
| **用户流程** | 用户流程是否合理？是否有死循环或断路？ |
| **数据结构** | 业务数据实体定义是否完整？（非技术视角） |

### 完整设计特有维度

| 评审维度 | 评审要点 |
|---------|---------|
| **界面设计** | 界面布局是否合理？组件结构是否清晰？ |
| **交互设计** | 交互规则是否明确？反馈机制是否完善？ |

### 高层设计特有维度

| 评审维度 | 评审要点 |
|---------|---------|
| **模块划分合理性** | 模块边界是否清晰？是否高内聚低耦合？模块粒度是否适中？ |
| **依赖关系正确性** | 模块间依赖关系是否正确？是否存在循环依赖？优先级排序是否合理？ |
| **核心旅程完整性** | 端到端用户旅程是否被模块完整覆盖？跨模块场景是否衔接？ |
| **可独立验证性** | 每个模块是否可以独立设计和验收？ |
| **拆分必要性** | 是否有必要拆分？拆分粒度是否过细或过粗？ |
| **递归拆分评估** | 需要进一步拆分的模块，其拆分方向建议是否合理？ |

### 模块设计特有维度

| 评审维度 | 评审要点 |
|---------|---------|
| **模块职责一致性** | 设计内容是否在模块职责范围内？是否有超出边界的设计？ |
| **依赖关系实现** | 与上游/下游模块的依赖关系是否在设计中正确体现？ |
| **数据接口清晰性** | 对外暴露的数据/功能是否清晰？与上游的数据获取是否明确？ |
| **与高层设计一致性** | 模块设计是否与 PRODUCT-DESIGN-HIGH-LEVEL.md 中的模块定义一致？ |
| **界面设计** | 界面布局是否合理？ |
| **交互设计** | 交互规则是否明确？ |

## 工作流程

### Step 1: 确认评审场景

检查项目中存在的设计文档，确定评审场景：

```
只有 PRODUCT-DESIGN.md → 完整设计评审
只有 PRODUCT-DESIGN-HIGH-LEVEL.md → 高层设计评审
存在 PRODUCT-DESIGN-{M}.md → 模块设计评审
```

### Step 2: 选择评审维度

根据评审场景选择对应的评审维度（通用 + 特有）。

### Step 3: 执行评审

1. 使用 `/review` skill 进入评审模式
2. 逐一检查对应的评审维度
3. 发现问题时记录：
   - 问题所在章节
   - 问题描述
   - 改进建议

### Step 4: 输出评审文档

根据场景输出对应的评审文档。

**注意**: 技术可行性不在此阶段评审，由 Technical Feasibility Analyst Agent 负责。

## 提示词样例

### 完整设计评审

```
请阅读当前项目目录下的 PRODUCT-DESIGN.md 和 BRD.md，对该文档进行专业评审。

评审标准:
1. 需求覆盖: 设计是否完整覆盖所有需求
2. 功能完整性: 每个功能模块描述是否完整
3. 用户流程: 用户流程是否合理
4. 界面设计: 界面布局是否合理
5. 交互设计: 交互规则是否明确
6. 数据结构: 业务数据实体定义是否完整

请将评审问题输出到 PRODUCT-DESIGN_REVIEW.md。
```

### 高层设计评审

```
请阅读当前项目目录下的 PRODUCT-DESIGN-HIGH-LEVEL.md 和 BRD.md，对高层设计和模块划分进行评审。

评审标准:
1. 需求覆盖: 高层设计是否覆盖所有业务需求
2. 模块划分合理性: 模块边界是否清晰？是否高内聚低耦合？粒度适中？
3. 依赖关系正确性: 模块间依赖是否正确？有无循环依赖？优先级合理？
4. 核心旅程完整性: 端到端旅程是否被模块覆盖？跨模块场景是否衔接？
5. 可独立验证性: 每个模块是否可独立设计和验收？
6. 拆分必要性: 是否有必要拆分？粒度是否合适？
7. 递归拆分评估: 需要进一步拆分的建议是否合理？

请将评审问题输出到 PRODUCT-DESIGN-HIGH-LEVEL_REVIEW.md。
```

### 模块设计评审

```
请阅读当前项目目录下的 PRODUCT-DESIGN-{ModuleName}.md、BRD.md 和 PRODUCT-DESIGN-HIGH-LEVEL.md，对该模块设计进行评审。

评审标准:
1. 需求覆盖: 模块设计是否覆盖了高层设计中该模块的职责
2. 模块职责一致性: 设计内容是否在模块职责范围内
3. 依赖关系实现: 与上下游模块的依赖关系是否正确体现
4. 数据接口清晰性: 对外暴露的数据/功能是否清晰
5. 与高层设计一致性: 是否与高层设计中的模块定义一致
6. 功能完整性: 功能描述是否完整
7. 用户流程: 流程是否合理
8. 界面设计: 界面布局是否合理
9. 交互设计: 交互规则是否明确
10. 数据结构: 数据实体定义是否完整

请将评审问题输出到 PRODUCT-DESIGN-{M}_REVIEW.md。
```
